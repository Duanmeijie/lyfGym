# lyfGym 健身房管理系统需求分析文档

## 1. 项目背景与目标

### 1.1 项目背景

随着健身行业的快速发展，健身房面临着日益增长的管理需求。传统的人工管理方式已经无法满足现代健身房对会员、教练、课程等信息的精细化管理要求。开发一套功能完善、性能稳定的健身房管理系统，能够有效提升健身房运营效率，降低管理成本，为会员提供更优质的服务体验。

### 1.2 项目目标

本项目旨在开发一套基于 Web 的健身房管理系统，主要目标包括：

- **会员管理**：实现会员信息的数字化管理，支持会员注册、信息修改、会员卡充值、状态管理等功能。
- **教练管理**：建立教练信息档案，展示教练专业特长，支持教练排课和课程预约。
- **课程管理**：实现课程排课、课程预约、课程统计等功能，支持多种课程类型。
- **数据可视化**：通过图表直观展示经营数据，为管理决策提供数据支持。
- **AI 助手**：集成 AI 智能助手，为会员提供健身问答服务。

---

## 2. 用户角色

本系统为单角色管理系统，主要用户为 **健身房管理员**，负责系统所有功能模块的操作。

| 角色 | 权限范围 | 说明 |
|------|----------|------|
| 管理员 | 全部 | 负责会员、教练、课程、数据的全面管理 |

## 3. 功能需求

### 3.1 登录与权限模块

#### 3.1.1 功能列表

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 用户登录 | 管理员输入用户名密码登录系统 | P0 |
| Token 认证 | 登录成功后返回 JWT Token，后续请求携带 Token | P0 |
| 路由守卫 | 未登录用户访问受限页面自动跳转登录页 | P0 |
| 退出登录 | 清除 Token 并跳转登录页 | P1 |

#### 3.1.2 业务流程

```
用户输入用户名密码 → 后端验证 → 返回 Token + 用户信息 → 前端存储 Token → 跳转首页
```

#### 3.1.3 约束条件

- 用户名密码错误返回明确提示
- Token 有效期设置为 24 小时
- 登出后清除所有本地存储的认证信息

---

### 3.2 会员管理模块

#### 3.2.1 功能列表

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 会员列表 | 分页展示所有会员，支持搜索和筛选 | P0 |
| 新增会员 | 填写姓名、手机号、会员类型、天数创建会员 | P0 |
| 编辑会员 | 修改会员基本信息、会员卡有效期 | P1 |
| 会员充值 | 为会员增加天数（30/60/90/180/365天） | P1 |
| 冻结/解冻 | 冻结或解冻会员账号 | P1 |
| 删除会员 | 删除会员记录（需数据合规性校验） | P2 |
| 即将过期提醒 | 筛选 7 天内即将过期的会员 | P2 |

#### 3.2.2 业务流程

```
新增会员：填写信息 → 手机号唯一性校验 → 创建会员 → 返回成功提示
会员充值：选择会员 → 选择充值天数 → 更新天数 → 刷新列表
删除会员：确认删除 → 校验是否有购买记录/余额 → 执行删除/拒绝
```

#### 3.2.3 数据模型

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(100) | NOT NULL | 姓名 |
| phone | VARCHAR(20) | NOT NULL, UNIQUE | 手机号 |
| type | ENUM | ('月卡','季卡','年卡') | 会员类型 |
| days_left | INT | DEFAULT 0 | 剩余天数 |
| status | ENUM | ('有效','过期','冻结') | 状态 |
| created_at | TIMESTAMP | DEFAULT NOW() | 创建时间 |

#### 3.2.4 约束条件

- 手机号唯一性校验：新增/修改时检查手机号是否已存在
- 删除前置条件：无购买记录且余额为0方可删除
- 冻结状态下会员无法享受服务

### 3.3 教练管理模块

#### 3.3.1 功能列表

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 教练列表 | 卡片式展示所有教练信息 | P0 |
| 教练搜索 | 按姓名/擅长领域搜索 | P1 |
| 新增教练 | 填写教练信息创建档案 | P0 |
| 编辑教练 | 修改教练信息 | P1 |
| 删除教练 | 删除教练档案 | P1 |
| 教练详情 | 查看教练详细简介和排课记录 | P1 |
| 预约课程 | 点击跳转到课程页面并筛选该教练课程 | P2 |
| 金牌标识 | 经验 > 5 年自动标识为金牌教练 | P1 |

#### 3.3.2 业务流程

```
新增教练：填写信息 → 保存 → 自动计算金牌标识 → 刷新列表
删除教练：确认删除 → 校验是否有未完成课程 → 执行删除/拒绝
查看详情：点击查看 → 弹出 Modal 展示详情和排课记录
```

#### 3.3.3 数据模型

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(100) | NOT NULL | 姓名 |
| specialty | VARCHAR(255) | - | 擅长领域 |
| bio | VARCHAR(1000) | - | 简介 |
| avatar_url | VARCHAR(500) | - | 头像URL |
| experience | INT | DEFAULT 0 | 经验年限 |
| is_gold | BOOLEAN | DEFAULT FALSE | 金牌标识 |
| created_at | TIMESTAMP | DEFAULT NOW() | 创建时间 |

#### 3.3.4 约束条件

- 删除前置条件：名下有未完成的课程禁止删除，需先转移课程
- 金牌标识逻辑：根据 experience 字段自动计算（> 5 年为金牌）

### 3.4 课程管理模块

#### 3.4.1 功能列表

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 课程统计 | 展示今日课程数、活跃课程数、总课时数 | P0 |
| 课程列表 | 分页展示课程，支持教练/状态筛选 | P0 |
| 新增课程 | 选择教练、填写课程信息创建课程 | P0 |
| 编辑课程 | 修改课程信息（已开始课程禁止改时间） | P1 |
| 删除课程 | 删除课程（已有预约禁止删除） | P1 |
| 时间冲突检测 | 同一教练同一时间不能重复排课 | P0 |

#### 3.4.2 业务流程

```
新增课程：选择教练 → 填写信息 → 冲突检测 → 创建课程 → 刷新列表
编辑课程：修改信息 → 已开始检查 → 保存 → 刷新列表
删除课程：确认删除 → 预约检查 → 执行删除/拒绝
```

#### 3.4.3 数据模型

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(100) | NOT NULL | 课程名称 |
| coach_id | BIGINT | NOT NULL, FK | 教练ID |
| type | VARCHAR(50) | - | 课程类型 |
| start_date | DATE | NOT NULL | 课程日期 |
| start_time | TIME | NOT NULL | 开始时间 |
| end_time | TIME | NOT NULL | 结束时间 |
| duration_hours | DECIMAL(4,1) | - | 时长 |
| max_capacity | INT | DEFAULT 20 | 最大人数 |
| booked_count | INT | DEFAULT 0 | 已预约人数 |
| is_active | TINYINT | DEFAULT 1 | 是否进行中 |
| created_at | DATETIME | DEFAULT NOW() | 创建时间 |

#### 3.4.4 约束条件

- 容量校验：max_capacity 必须大于 0
- 冲突检测：同一教练同一时间（时间有重叠）不能排课
- 编辑限制：已经开始的课程禁止修改时间
- 删除前置条件：已有会员预约的课程禁止直接删除

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 列表加载时间 | < 500ms |
| 页面响应时间 | < 1s |
| 并发用户数 | 支持 10+ 用户同时在线 |

### 4.2 安全性要求

| 指标 | 要求 |
|------|------|
| 密码加密 | 存储时使用 MD5 加密 |
| Token 认证 | 所有 API 请求需携带有效 Token |
| SQL 注入防护 | 使用参数化查询 |
| 错误信息脱敏 | 不在前端直接暴露数据库错误信息 |

### 4.3 兼容性要求

| 指标 | 要求 |
|------|------|
| 浏览器支持 | Chrome / Edge / Firefox / Safari 最新版本 |
| 屏幕适配 | 支持 1024px 以上分辨率 |

### 4.4 可维护性要求

| 指标 | 要求 |
|------|------|
| 代码规范 | 遵循 ESLint 规范 |
| 模块化 | 前后端分离，模块职责清晰 |
| 日志记录 | 后端关键操作记录日志 |
