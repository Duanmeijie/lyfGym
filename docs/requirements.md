# lyfGym 健身房管理系统需求分析文档

## 1. 项目背景与目标

### 1.1 项目背景

随着健身行业的快速发展，健身房面临着日益增长的管理需求。传统的人工管理方式已经无法满足现代健身房对会员、教练、课程等信息的精细化管理要求。开发一套功能完善、性能稳定的健身房管理系统，能够有效提升健身房运营效率，降低管理成本，为会员提供更优质的服务体验。

### 1.2 项目目标

本项目旨在开发一套基于 Web 的健身房管理系统，主要目标包括：

- **会员管理**：实现会员信息的数字化管理，支持会员注册、信息修改、会员卡充值、状态管理等功能。
- **教练管理**：建立教练信息档案，展示教练专业特长，支持教练排课和课程预约。
- **课程管理**：实现课程排课、课程预约、课程统计等功能，支持多种课程类型。
- **商品管理**：管理健身房商品（营养补剂、运动装备、健身服饰等）的进销存。
- **订单管理**：跟踪所有交易记录（会员卡购买、商品购买、课程购买）。
- **预约管理**：会员课程预约全流程管理。
- **营收统计**：多维度收入数据分析与可视化。
- **公告管理**：发布系统公告、活动通知。
- **数据可视化**：通过图表直观展示经营数据，为管理决策提供数据支持。
- **AI 助手**：集成 AI 智能助手，为会员提供健身问答服务。

## 2. 用户角色

本系统为单角色管理系统，主要用户为 **健身房管理员**，负责系统所有功能模块的操作。

|------|----------|------|
| 管理员 | 全部 | 负责会员、教练、课程、商品、订单等全面管理 |

## 3. 功能需求

### 3.1 登录与权限模块

#### 3.1.1 功能列表

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 用户登录 | 管理员输入用户名密码登录系统 | P0 |
| Token 认证 | 登录成功后返回 Token，后续请求携带 Token | P0 |
| 路由守卫 | 未登录用户访问受限页面自动跳转登录页 | P0 |
| 退出登录 | 清除 Token 并跳转登录页 | P1 |
| 用户信息管理 | 查看/更新管理员个人信息 | P2 |

#### 3.1.2 业务流程

```
用户输入用户名密码 → 后端验证（先查数据库，后回退硬编码） → 返回 Token + 用户信息 → 前端存储 Token → 跳转首页
```

#### 3.1.3 约束条件

- 用户名密码错误返回明确提示
- 登出后清除所有本地存储的认证信息

### 3.2 会员管理模块

#### 3.2.1 功能列表

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 会员列表 | 展示所有会员，支持搜索和筛选 | P0 |
| 新增会员 | 填写姓名、手机号、会员类型、天数创建会员 | P0 |
| 编辑会员 | 修改会员基本信息、会员卡有效期 | P1 |
| 会员充值 | 为会员增加天数（30/60/90/180/365天） | P1 |
| 冻结/解冻 | 冻结或解冻会员账号 | P1 |
| 删除会员 | 删除会员记录（需数据合规性校验） | P2 |
| 即将过期提醒 | 筛选 7 天内即将过期的会员 | P2 |
| 会员详情 | 查看会员完整档案，包含体测记录、预约历史、订单记录、签到记录 | P1 |
| 体测记录 | 记录和跟踪会员体重、体脂率、BMI等身体指标变化 | P1 |
| 会员签到 | 每日签到记录，防止同日重复签到 | P1 |

#### 3.2.2 业务流程

```
新增会员：填写信息 → 手机号唯一性校验 → 创建会员 → 返回成功提示
会员充值：选择会员 → 选择充值天数 → 更新天数 → 刷新列表
删除会员：确认删除 → 校验是否有购买记录/余额 → 执行删除/拒绝
会员详情：点击会员名 → 跳转详情页 → Tabs切换查看体测/预约/订单/签到
```

#### 3.2.3 数据模型

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(100) | NOT NULL | 姓名 |
| phone | VARCHAR(20) | NOT NULL, UNIQUE | 手机号 |
| type | ENUM | ('月卡','季卡','年卡') | 会员类型 |
| days_left | INT | DEFAULT 0 | 剩余天数 |
| status | ENUM | ('有效','过期','冻结') | 状态 |
| gender | VARCHAR(10) | DEFAULT '男' | 性别 |
| birthday | DATE | - | 生日 |
| weight | DECIMAL(5,1) | - | 体重(kg) |
| body_fat | DECIMAL(4,1) | - | 体脂率(%) |
| emergency_contact | VARCHAR(50) | - | 紧急联系人 |
| emergency_phone | VARCHAR(20) | - | 紧急联系电话 |
| created_at | TIMESTAMP | DEFAULT NOW() | 创建时间 |

#### 3.2.4 约束条件

- 手机号唯一性校验：新增/修改时检查手机号是否已存在
- 删除前置条件：无购买记录且余额为0方可删除
- 冻结状态下会员无法享受服务

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 列表加载时间 | < 500ms |
| 页面响应时间 | < 1s |
| 并发用户数 | 支持 10+ 用户同时在线 |

### 4.2 安全性要求

| 指标 | 要求 |
|------|------|
| Token 认证 | 所有 API 请求需携带有效 Token |
| SQL 注入防护 | 使用参数化查询 |
| 错误信息脱敏 | 不在前端直接暴露数据库错误信息 |

### 4.3 兼容性要求

| 指标 | 要求 |
|------|------|
| 浏览器支持 | Chrome / Edge / Firefox / Safari 最新版本 |
| 屏幕适配 | 支持 1024px 以上分辨率，响应式设计 |

### 4.4 可维护性要求

| 指标 | 要求 |
|------|------|
| 模块化 | 前后端分离，模块职责清晰 |
| 代码规范 | 遵循 Vue 3 Composition API 规范 |
| 数据填充 | 支持一键生成测试数据 |

## 6. 项目技术栈

### 后端
- Node.js + Express.js
- MySQL (mysql2/promise)
- JWT Token 认证

### 前端
- Vue 3 (Composition API + `<script setup>`)
- Vite 构建工具
- Vue Router 路由管理
- Pinia 状态管理
- Axios HTTP 请求
- ECharts 数据可视化
- Iconify 图标库

### 数据库
- MySQL 8.0+
- 12张表：users, members, coaches, courses, bookings, orders, products, member_body_records, announcements, check_ins, activity_logs
